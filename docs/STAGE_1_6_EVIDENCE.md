# Stage 1.6 Evidence Record

## Scope

Stage 1.6 establishes reproducibility as an explicit simulation invariant. For the same source/model revision, locked dependency graph, seed and accepted command journal, the simulation must reconstruct the same authoritative state independent of playback speed or renderer sampling.

## Implemented determinism controls

- canonical authoritative state digest over the validated Stage 1.5 binary state representation
- digest coverage for pending commands, executed-command history, Event Ledger and next IDs
- counter-based deterministic random sampling keyed by seed + tick + stable stream + ordinal
- no mutable global RNG cursor
- accepted-command journal containing executed and still-pending commands exactly once
- fresh-engine command journal replay using recorded submission and effective dates
- replay rejection for malformed/non-contiguous journals
- exact save/restore digest equality
- manual-vs-365x authoritative-state equality
- 10,000-tick replay equality
- committed `Cargo.lock` copied from the dependency graph resolved by passing GitHub CI
- `--locked` enforcement for Clippy, unit tests and headless execution

## Authoritative state digest

The acceptance digest is computed from the same canonical `state.bin` bytes used by Stage 1.5 save/restore. This prevents persistence and determinism from silently disagreeing about which fields are authoritative.

The digest therefore covers:

- world seed/date/elapsed days
- pending command queue
- executed-command history
- Event Ledger
- next `CommandId`
- next `EventId`

A test confirms that adding a future pending command changes the authoritative digest before the command executes.

The older minimal world-only `state_digest()` remains temporarily for compatibility with earlier infrastructure tests, but it is no longer the Stage 1.6 reproducibility acceptance hash.

## Counter-based random contract

Future stochastic simulation logic receives deterministic samples through:

```text
(seed, current tick, stable stream id, ordinal) -> u64
```

The generator is stateless. Reordering calls between independent streams does not shift another subsystem's sequence. Tests verify repeatability and sensitivity to seed, tick, stream and ordinal.

## Command journal replay

The accepted-command journal merges executed and pending commands and restores original acceptance order by monotonic `CommandId`.

Replay starts from a clean engine with the original seed, submits each command on its recorded submission date, preserves the recorded execution date and ID, and advances to the target tick.

Validated cases include:

- replay with an immediate command already executed
- replay with later AI/user commands
- replay with a command accepted on the current target date but not yet followed by a tick
- exact 10,000-tick replay

The replayed engine must match the original snapshot, command history, Event Ledger, next IDs and authoritative digest.

## Dependency locking

The repository now contains `Cargo.lock` generated by the dependency graph actually resolved in GitHub Actions.

Locked resolution includes, among other packages:

- `serde 1.0.229`
- `serde_json 1.0.151`
- `syn 3.0.3`

The exact registry checksums are stored in the committed lockfile. CI now uses:

```text
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo run --locked -p simulation-runner --quiet
```

A manifest/lockfile mismatch therefore fails validation instead of silently selecting a new dependency graph.
